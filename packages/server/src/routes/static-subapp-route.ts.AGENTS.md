# static-subapp-route.ts — index

Static sub-apps served same-origin off the dashboard. Exports `MOBILE_PREFIX` (`"/mobile"`), `LINKS_PREFIX` (`"/links"`), `registerStaticSubAppRoute(fastify, prefix)`, private `normalizePrefix`. A sub-app is a directory of plain files in the repo's top-level `public/<name>/`; Vite copies `public/` verbatim into the client build (`packages/client/dist/<name>/`) and `@fastify/static` already serves that at `/`, so `<prefix>/` needs NO route. The helper's whole job is the SLASHLESS path: `@fastify/static` matches files not directories, so `/mobile` would fall through to the SPA not-found handler and hand the caller the full desktop app; it answers with a 308 to the slashed form. Idempotent per instance+prefix via a `Set` hung on the instance, so two plugins may both ask for the same prefix without a duplicate-route error. Registered before `@fastify/static`, like `registerManifestRoute`. Sub-app files are deliberately OUTSIDE the network guard's jurisdiction — same status as the SPA shell and `/manifest.json`, because they are static bytes with no capability; every byte of DATA a sub-app reads comes from `/api/...` or `/ws`, which ARE guarded. See change: add-same-origin-mobile-poc, add-same-origin-links-page.
